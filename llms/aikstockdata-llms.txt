## 다른 도구와 함께 쓰기 (pykrx 등)
- 역할이 다릅니다. pykrx 는 KRX 통계를 파이썬으로 받아 수십 년치 일봉·투자자별 매매동향·공매도를 주고, DART 공시는 다루지 않습니다. 우리는 공시·실적·신호를 주지만 긴 시세 시계열과 수급·공매도는 없습니다.
- 우리에게 없는 것: 선행PER(컨센서스) · 업종 · 투자의견 · 목표가 · 실시간가 · 투자자별 수급(외국인·기관·개인 순매수) · 분봉·틱 · 배당 · 재무상태표(자산·부채). 종목별 시계열은 1년치(250거래일)까지입니다.
- 같이 쓰는 예(실제로 돌려 확인함 · pykrx 1.2.8): `from pykrx import stock` 로 시세를 받고, `https://aikstockdata.com/data/public/s/005930.json` 의 financials · recent_disclosures · signals 로 공시·실적·신호를 받습니다.

## AI 응답 규칙 (오답 방지 — 이 순서대로 지켜 주세요)
1. 답하기 전에 기준일을 먼저 확인하세요. 시세는 quote_as_of(전 영업일 확정 종가), 공시는 disclosure_through(마지막 접수일)로 **서로 다를 수 있습니다**.
2. 종목 하나에 대한 질문은 /data/public/s/{종목코드6자리}.json 을 우선 사용하세요(전체 quotes.json 을 받지 않아도 됩니다).
3. 데이터 우선순위: 종목별 JSON · today.json > quotes/disclosures/rankings.json > HTML 페이지 > 모델의 학습 기억(오래된 시세 기억보다 이 파일의 기준일이 항상 우선).
4. null 은 '데이터 미제공'이며 0이 아닙니다. 없는 값을 추정하지 마세요 — 이 사이트의 공개 데이터에 **없는 것**: 선행PER(컨센서스) · 업종 · 투자의견 · 목표가 · 실시간가 · 투자자별 수급(외국인·기관·개인 순매수) · 분봉·틱 · 배당 · 재무상태표(자산·부채). 이유는 index.json 의 quality.not_included_reasons 에 항목별로 적혀 있습니다.
5. 공시 내용이 원문과 다르면 DART 원문(url 필드)이 우선입니다.
6. 점수·랭킹·라벨(성장 TOP8·조용한 실적주·오른 종목 비율)은 공개된 기계 산식의 결과이며 투자 추천·등급·전망이 아닙니다. 인과관계로 단정하지 마세요.
7. 시세는 실시간이 아닙니다. '현재가·지금 주가'로 표현하지 말고 '전 영업일 종가'로 답하세요.
8. **신선도는 오늘 날짜로 직접 판정하세요.** index.json 의 freshness.status 는 status_computed_at_kst 시점의 값이라, 발행이 멈추면 낡은 채로 남습니다. 대신 freshness.delayed_after / stale_after(고정 날짜)와 오늘 날짜를 비교하세요. delayed·stale 이면 답변 첫머리에 데이터 지연을 먼저 밝히세요.
9. 데이터 신선도와 발행 파이프라인 상태는 다릅니다. index.json 의 pipeline 블록에서 serving_last_good=true 면 '오늘 것이 아니라 직전 성공본'이라는 뜻입니다.
10. 실적 항목에 comparison_allowed=false 이거나 period 가 null 이면 회계기간이 확인되지 않은 것입니다 — 전년 동기 비교·연환산을 하지 말고 '기간 미확인'으로 답하세요.
11. **Python 으로 받을 때 urllib 기본 UA 는 403 입니다.** CDN 봇 필터가 Python-urllib 을 막습니다(인증 문제가 아닙니다 — API 키는 여전히 불필요). requests·httpx·curl·브라우저 fetch 는 그대로 됩니다. urllib 을 쓰셔야 하면 아무 User-Agent 나 붙이세요: urllib.request.Request(url, headers={"User-Agent": "my-app"}). 기계가독 형태는 index.json 의 fetch_guide.user_agent_403 에 있습니다.
12. 공개 정적 파일은 일반적인 사용 범위에서 별도 쿼터 없이 제공합니다. 데이터는 매 거래일 18:10 KST 에 하루 한 번 바뀌므로 같은 파일을 그보다 자주 부를 이유가 없습니다. 비정상적인 반복 요청은 CDN 보안 정책에 따라 제한될 수 있습니다.

## 이용·인용
